# Contributing

Corrections and additions are welcome, particularly from practitioners who have run an AI procurement and found something these tools miss.

## Most useful contributions

**Corrections.** If a tool routes something wrongly, misses a risk, or states something that is no longer accurate, open an issue and say what happened. Real failure cases are more valuable than suggestions.

**Rate and market updates.** AI pricing moves quickly. If a figure in this repository is out of date, open an issue with the current figure and a link to the vendor's own documentation.

**New routes and edge cases.** The five routes cover what is common. If you have hit an AI purchase that does not fit any of them cleanly, that is worth knowing about.

**Jurisdiction mappings.** The governance references lean Ontario and Canadian public sector. Mappings to other jurisdictions are welcome as separate files rather than edits to existing tools.

## Standards for a new tool

Tools in this repository follow a consistent structure so that they are predictable to use. A new skill should include Purpose, When to Use, Do Not Use, Required Inputs, a Missing Information Rule, numbered Workflow steps, an Output Format, Review Checks, Human Review, Guardrails, and an example request.

Three principles apply to everything here:

1. A tool prepares work for a human to judge. It does not judge.
2. A tool that cannot answer says so rather than guessing.
3. Any figure carries its date and its source.

## What will not be merged

- Anything that presents a tool output as an approval, a clearance, or legal advice
- Vendor promotional material, or tools that route toward a particular vendor
- Figures without a source
- Content that would identify a live procurement, a bidder, or a negotiation position

## How to contribute

Open an issue first for anything substantial, so the approach can be agreed before the work is done. Small corrections can go straight to a pull request.
